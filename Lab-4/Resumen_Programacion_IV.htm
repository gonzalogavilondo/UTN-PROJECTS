Unidad 01 · Estructura

HTML declara qué existe

HTML es declarativo: describe el documento. El navegador transforma esa jerarquía en un árbol de objetos llamado DOM.

01

Documento

<!DOCTYPE>, <html>, <head>, metadatos, título y <body>.

02

Semántica

header, nav, main, section, article, aside y footer.

03

Contenido

Encabezados, párrafos, enlaces, listas, imágenes, tablas y controles de formulario.

Estructura mínima razonada

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi aplicación</title>
  <link rel="stylesheet" href="style.css">
  <script type="module" src="app.js"></script>
</head>
<body>
  <header><h1>Título</h1></header>
  <main><section>Contenido principal</section></main>
</body>
</html>
¿Cuándo usar section, article y div?

section agrupa un tema y normalmente tiene encabezado. article contiene una unidad independiente, como una tarjeta de libro. div agrupa sin significado semántico, generalmente para layout o scripting. Elegí primero el elemento que mejor explique el contenido.

Formularios: datos con nombre

Un control útil necesita una etiqueta asociada. El for del label coincide con el id del campo; el atributo name identifica el dato al enviarlo. required, tipos como email o number y otros atributos aportan validación nativa.

<form id="form-libro">
  <label for="titulo">Título</label>
  <input id="titulo" name="titulo" type="text" required>
  <button type="submit">Agregar</button>
</form>

Tablas: sólo para relaciones entre filas y columnas

Una tabla de datos usa caption, thead, tbody, filas tr, encabezados th con scope y celdas td. No se usa para maquetar una página.

Unidad 02 · Presentación

CSS selecciona cajas y aplica reglas

Cada regla combina un selector con declaraciones. Si varias reglas compiten, importan la cascada, la especificidad y el orden.

Box model: todo elemento ocupa una caja

De adentro hacia afuera

  1. content: texto o hijos.
  2. padding: aire interior.
  3. border: límite visible.
  4. margin: separación exterior.

La regla que evita sorpresas

* {
  box-sizing: border-box;
}

Así, el ancho declarado ya incluye padding y borde.

¿Por qué margin y padding no son intercambiables?

padding forma parte de la caja visual y recibe su fondo; separa contenido y borde. margin queda afuera y separa cajas entre sí. Elegir uno u otro cambia tamaño, fondo y comportamiento del layout.

Unidad 03 · Layout adaptable

Flexbox, Grid y responsive

Flexbox ordena contenido en un eje; Grid controla filas y columnas simultáneamente. Se combinan con medidas flexibles y media queries cuando el diseño realmente necesita cambiar.

Flexbox · una dimensión

Ideal para navegación, filas de botones, alineación y contenido que fluye.

.acciones {
  display: flex;
  flex-wrap: wrap;
  gap: .5rem;
}
.acciones button { flex: 1 1 140px; }

justify-content actúa sobre el eje principal; align-items, sobre el transversal.

Grid · dos dimensiones

Ideal para estructuras generales y colecciones alineadas en filas y columnas.

.catalogo {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(220px, 1fr));
  gap: 1rem;
}

auto-fit agrega tantas columnas como entren; minmax marca su límite.

Responsive no significa “muchas media queries”

  • Incluí meta viewport.
  • Preferí anchos relativos, max-width, min(), clamp(), fr y layouts que puedan envolver contenido.
  • Empezá por una columna y agregá complejidad cuando exista espacio: enfoque mobile-first.
  • Usá @media cuando debe cambiar la estructura, interacción u orientación.
  • No bloquees zoom y mantené controles táctiles cómodos.
main {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1.5rem;
}

@media (min-width: 800px) {
  main {
    grid-template-columns: 1fr 2fr;
    grid-template-areas:
      "form catalogo"
      "filtros catalogo";
  }
}
Decisión rápida: ¿Flexbox o Grid?

Si pensás “quiero ordenar esta fila o columna”, probá Flexbox. Si pensás “quiero definir qué ocupa cada fila y columna”, probá Grid. En BiblioTech, Grid construye el layout principal y también la cuadrícula de tarjetas; Flexbox acomoda los botones dentro de cada tarjeta.

Unidad 04 · Lógica

JavaScript transforma datos

Antes del DOM están los fundamentos: valores, variables, arreglos, objetos, funciones, decisiones y ciclos. Una interfaz dinámica es lógica aplicada a datos.

Datos

Primitivos, arreglos y objetos. Los arreglos ordenan elementos; los objetos reúnen propiedades con nombre.

Procesos

Las funciones reciben parámetros, ejecutan una tarea y pueden devolver un resultado con return.

Decisiones

if, ternario, switch y ciclos permiten elegir y repetir según el estado.

const libros = [
  { titulo: "1984", genero: "Ciencia ficción" },
  { titulo: "Rayuela", genero: "Novela" }
];

function filtrarPorGenero(lista, genero) {
  return lista.filter((libro) => libro.genero === genero);
}

const novelas = filtrarPorGenero(libros, "Novela");
Métodos de arreglos: qué pregunta responde cada uno
MétodoPreguntaResultado
find¿Cuál es el primer elemento que cumple?Un elemento o undefined.
filter¿Cuáles cumplen?Un arreglo nuevo.
map¿Cómo transformo cada elemento?Un arreglo nuevo del mismo largo.
forEach¿Qué acción ejecuto por cada elemento?No produce un arreglo nuevo.
reduce¿Cómo acumulo todo en un único valor?Un acumulador.
Referencia. Los objetos y arreglos pueden compartir la misma referencia. Copiar con {...objeto} o [...arreglo] crea una copia superficial; los objetos anidados siguen compartiéndose.
Unidad 05 · Interacción

DOM y eventos conectan todo

El DOM es la representación del HTML en memoria. JavaScript consulta nodos, cambia texto o clases, crea elementos y registra funciones que reaccionan a eventos.

SeleccionarquerySelector

const formulario = document.querySelector("#form-libro");

formulario.addEventListener("submit", function (evento) {
  evento.preventDefault();
  const titulo = document.querySelector("#titulo").value.trim();
  console.log(titulo);

Modificar

  • textContent: reemplaza texto.
  • classList.add/toggle: cambia estado visual mediante CSS.
  • createElement: crea un nodo.
  • append/appendChild: lo inserta.
  • remove: lo elimina.

Escuchar

  • click: activación.
  • input: cada modificación del campo.
  • change: valor confirmado.
  • submit: envío de formulario.
  • keydown: tecla presionada.
¿Qué es bubbling y por qué sirve la delegación?

Un evento comienza en el elemento objetivo y se propaga por sus antecesores. Gracias a eso, un único listener en un contenedor puede manejar botones creados ahora o más adelante. Se consulta event.target para saber qué elemento originó la acción.

Unidad 06 · TP Integrador

BiblioTech explicado de punta a punta

BiblioTech es una aplicación de catálogo ejecutada completamente en el navegador. Integra formulario, filtros, tarjetas responsivas, objetos, clases, módulos, eventos, renderizado dinámico y persistencia local.

index.html

Declara la interfaz inicial: formulario, buscador, selector de género y contenedor vacío del catálogo.

CSS/style.css

Define layout con Grid, tarjetas adaptables, controles, estados favorito/prestado y cambio a una columna.

JS/biblioteca.js

Contiene el modelo: clases Libro y Biblioteca, reglas, filtrado y persistencia.

JS/render.js

Convierte objetos Libro en nodos del DOM y reconstruye tarjetas y opciones de género.

JS/app.js

Compone todo: crea la biblioteca, selecciona el DOM, registra eventos y coordina modelo y vista.

localStorage

API del navegador. Conserva el arreglo serializado con la clave bibliotech-libros.

Abrir BiblioTech Ver arquitectura interactiva

Primero: qué existe antes de ejecutar JavaScript

El HTML ya ofrece campos y secciones utilizables. El catálogo comienza como un div vacío porque sus tarjetas dependen de los datos. El CSS ya conoce clases como .libro-favorito y .libro-prestado; JavaScript sólo decide cuándo aplicarlas.

El navegador carga el módulo principal

index.html incluye app.js con type="module". Eso permite importar explícitamente Biblioteca, renderizarGeneros y renderizarLibros.

import { Biblioteca } from "./biblioteca.js";
import { renderizarGeneros, renderizarLibros } from "./render.js";

Se crea el estado central

new Biblioteca("bibliotech-libros") crea un objeto con tres datos: clave de almacenamiento, arreglo libros y proximoId.

Después, cargarCatalogo() consulta localStorage. Si no hay datos, usa cinco libros iniciales. Si hay JSON, lo parsea y vuelve a construir cada instancia de Libro.

Se conectan variables con elementos del DOM

querySelector guarda referencias al formulario, buscador, selector y catálogo. Desde ese momento, app.js puede leer valores y escuchar acciones.

const formulario = document.querySelector("#form-libro");
const buscador = document.querySelector("#buscar");
const filtroGenero = document.querySelector("#filtro-genero");
const catalogo = document.querySelector("#catalogo-libros");

Se registran cuatro entradas de usuario

submit agrega; input busca mientras se escribe; change reacciona al género; click delegado procesa todos los botones del catálogo.

Agregar un libro

El listener evita la recarga con preventDefault(), lee y limpia los campos, convierte el año a número y arma datosLibro. El modelo crea una instancia con ID único, la agrega al arreglo, incrementa el ID y guarda.

const datosLibro = {
  titulo: campoTitulo.value.trim(),
  autor: campoAutor.value.trim(),
  genero: campoGenero.value.trim(),
  anio: Number(campoAnio.value)
};
biblioteca.agregarLibro(datosLibro);

Filtrar sin modificar el catálogo original

filtrarLibros normaliza la búsqueda a minúsculas, recorre el catálogo y exige dos condiciones: que el título contenga el texto y que el género coincida o esté vacío. Devuelve otro arreglo para mostrar.

const coincideTitulo = libro.titulo.toLowerCase().indexOf(texto) !== -1;
const coincideGenero = generoSeleccionado === "" ||
                       libro.genero === generoSeleccionado;

Cambiar favorito o préstamo

Los botones renderizados llevan data-id y data-accion. El listener del contenedor lee esos atributos, busca el libro por ID y ejecuta alternarFavorito() o alternarPrestado(). Ambos métodos invierten un booleano.

this.favorito = !this.favorito;
this.prestado = !this.prestado;

Persistir significa serializar

localStorage sólo guarda texto. JSON.stringify(this.libros) convierte el arreglo en JSON; JSON.parse revierte esa conversión al cargar. Como JSON no conserva métodos, la carga crea de nuevo cada Libro.

Renderizar reconstruye la vista

renderizarLibros vacía el catálogo y crea una tarjeta por objeto. Usa textContent y createTextNode, evitando interpretar los datos como HTML. Si no hay resultados, muestra un estado vacío.

renderizarGeneros obtiene géneros únicos, los ordena y reconstruye el select, intentando conservar la opción elegida.

CSS traduce el estado a una apariencia

Si favorito === true, render agrega .libro-favorito; si prestado === true, agrega .libro-prestado. CSS decide el borde y el fondo. La regla de negocio queda en JavaScript y la presentación en CSS.

La idea arquitectónica central. app.js no dibuja tarjetas ni implementa reglas internas del libro. Coordina. biblioteca.js no busca elementos HTML. Modela datos. render.js no decide cómo persistir. Presenta. Esa separación hace que el programa sea más fácil de entender y cambiar.

Detalles importantes que conviene poder explicar

¿Por qué se usa delegación de eventos en el catálogo?

Las tarjetas y sus botones se destruyen y recrean al renderizar. Un listener colocado en cada botón tendría que volver a registrarse. El listener del contenedor permanece y recibe los clics por bubbling.

¿Por qué se calcula proximoId después de cargar?

Para que un libro nuevo no reutilice un ID existente. Se busca el mayor ID y se deja proximoId en uno más. El ID conecta el botón visible con el objeto correcto.

¿Qué cambia al filtrar?

No cambia biblioteca.libros. Sólo se crea librosFiltrados y se renderiza esa selección. Por eso borrar el texto o elegir “Todos” puede volver a mostrar el catálogo completo.

¿Qué pasaría si quitamos cada tecnología?

Sin JavaScript queda la estructura y el estilo, pero no se agregan, filtran ni cambian libros. Sin CSS la aplicación conserva estructura y comportamiento, pero pierde layout y estados visuales. Sin HTML no existen los puntos de entrada que CSS selecciona y JavaScript escucha.

Unidad 07 · Método

Cómo razonar un error

No cambies código al azar. Seguí el dato desde su origen hasta la pantalla y comprobá cada frontera.

  1. Reproducí: escribí la acción exacta que falla.
  2. Inspeccioná consola: empezá por el primer error, archivo y línea.
  3. Verificá selección: ¿querySelector devuelve un elemento o null?
  4. Verificá evento: ¿el listener se registra y la callback se ejecuta?
  5. Verificá dato: ¿tipo, valor, ID y propiedad son los esperados?
  6. Verificá estado: ¿el arreglo u objeto cambió?
  7. Verificá persistencia: ¿el JSON guardado refleja el cambio?
  8. Verificá render: ¿la función recibió los datos correctos y actualizó el contenedor?
  9. Verificá CSS: ¿la clase existe, coincide y no pierde por cascada?

Si el botón no hace nada

Revisá type, listener, selector, bubbling, event.target y atributos data-*.

Si se pierde al recargar

Revisá llamada a guardar, clave usada, JSON válido y reconstrucción durante la carga.

Si filtra mal

Revisá normalización, comparación exacta/parcial y combinación de condiciones con && u ||.

Si se ve mal

Inspeccioná box model, ancho disponible, selector aplicado, especificidad y breakpoint activo.

Preguntas para explicar en voz alta

Explicá el recorrido completo al agregar un libro.

Submit → preventDefault → lectura y normalización de campos → objeto de datos → Biblioteca.agregarLibro → nueva instancia Libro → push → incremento de ID → JSON.stringify y localStorage → actualización de géneros → filtrado → renderizado de tarjetas.

Explicá la diferencia entre estado y representación.

El estado es la información del programa: libros y booleanos favorito/prestado. La representación es cómo ese estado aparece en el DOM. Render conecta ambos; CSS traduce las clases resultantes a estilos.

Explicá por qué Grid no modifica el DOM.

Grid altera el algoritmo de layout aplicado a los hijos de un contenedor. Los nodos, sus padres, hijos y hermanos siguen siendo los mismos; sólo cambia dónde y cuánto se dibujan.
